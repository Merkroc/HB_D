# Открытка-альбом для Даши ♡

Интерактивная открытка ко дню рождения: конверт с сургучной печатью, письмо,
8 глав фотоальбома с «живыми» кадрами (Live Photos), лента живых мгновений,
пожелания, торт со свечами и финал. Чистые HTML + CSS + JS, без библиотек и сборки.

**Главный сценарий — телефон.** Крупные тапы, свайпы, никаких «наведи мышку»,
экономия трафика. Публикуется на **GitHub Pages**.

---

## Публикация на GitHub Pages

### Итог, к которому придём

Ссылка вида `https://ваш-логин.github.io/dasha-2611/` — открывается на любом телефоне.
Ниже два пути: автоматический (через батник, нужен установленный Git) и вручную.

### Путь 1 — батник (быстрее всего)

1. **Создайте пустой публичный репозиторий**: [github.com/new](https://github.com/new).
   - имя нейтральное, например `dasha-2611`;
   - **не** добавляйте README и `.gitignore`;
   - видимость — **Public** (для бесплатного Pages иначе никак).
2. Запустите `Опубликовать на GitHub.bat` в этой папке.
   - он проверит сайт, обновит папку «Публикация», сделает git-коммит
     и попросит вставить ссылку на репозиторий;
   - при первом запуске откроется окно входа в GitHub — подтвердите.
3. Включите сайт (один раз): в репозитории **Settings → Pages** →
   *Source: Deploy from a branch* → **Branch: main**, папка **/(root)** → **Save**.
4. Через 1–2 минуты ссылка появится вверху страницы Pages. Отправляйте её Даше.

> Если Git не установлен — поставьте [Git for Windows](https://git-scm.com/download/win)
> или [GitHub Desktop](https://desktop.github.com) и загляните в «Путь 2».

### Путь 2 — без командной строки (GitHub Desktop или сайт)

**GitHub Desktop:**
1. Запустите `Подготовить к публикации.bat` — появится папка «Публикация»
   (в ней только сайт, без оригиналов).
2. В GitHub Desktop: *File → Add local repository* → выберите папку «Публикация»
   → он предложит создать здесь репозиторий → **Publish repository**,
   снимите галочку «Keep this code private».
3. Дальше — включить Pages, как в шагах 3–4 выше.

**Через сайт GitHub (если совсем без программ):**
1. Создайте пустой публичный репозиторий.
2. `Add file → Upload files` и перетащите содержимое папки «Публикация».
   За один раз GitHub берёт до 100 файлов, а их 127 — загрузите в два приёма
   (например, сначала `index.html`, `css`, `js`, `robots.txt`, `.nojekyll`,
   потом `assets`).
3. Не забудьте файл `.nojekyll` (создаётся скриптом; если загружаете вручную —
   `Add file → Create new file`, имя `.nojekyll`, содержимое пустое).
4. Включите Pages, как в шагах 3–4 выше.

### Обновить открытку после правок

1. Внесите правки в проект (текст письма, подпись и т.п.).
2. Запустите `Опубликовать на GitHub.bat` — он обновит «Публикацию»,
   добавит новый коммит и отправит его. GitHub Pages обновится за 1–2 минуты.

> GitHub отдаёт файлы через CDN и кэширует их ~10 минут. Если после обновления
> видна старая версия — подождите или обновите страницу с зажатым Shift.

## ⚠️ Важно про приватность

- GitHub Pages на бесплатном тарифе работает **только из публичного репозитория**,
  то есть фотографии технически лежат в открытом доступе (хотя мы просим поисковики
  не индексировать: `<meta name="robots" content="noindex">` + `robots.txt`).
  Если это критично — используйте GitHub Pro (приватный репозиторий + Pages)
  или другой хостинг, например [Netlify Drop](https://app.netlify.com/drop)
  (там не нужен публичный репозиторий).
- В папку «Публикация» **не попадают оригиналы** из `iCloud Photos` — там
  высокое разрешение и геометки (место съёмки). Никогда не загружайте в репозиторий
  всю папку проекта целиком, только «Публикацию».
- Берите нейтральное имя репозитория, чтобы по нему нельзя было угадать содержимое.

## Проверка перед публикацией

```bat
python tools\check_site.py
```
Проверяет, что все фото/видео на месте, что регистр путей совпадает
(GitHub Pages — Linux, регистр важен) и что нет абсолютных путей, ломающихся
в подпапке `github.io/имя-репозитория/`.

Посмотреть локально «как на хостинге» можно батником `Открыть на телефоне.bat`
(адрес для телефона в той же Wi-Fi сети).

## Что можно (и стоит) поменять

### 1. Подпись, цифры и даты

Всё в одном месте — `js/app.js`, самом верху файла:
```js
var CONFIG = {
  sender: 'твой Белоус',     // подпись в письме: «— твой Белоус»
  albumDays: 77,             // «77 дней в альбоме» (и столько же в подзаголовке обложки)
  albumFrom: '26 сентября',  // начало в строке «с … по …»
  albumTo: '12 декабря'      // конец в строке «с … по …»
};
```

- `albumDays` — просто число, любое. Если поставить `0` — посчитается автоматически
  по датам самого первого и самого последнего фото.
- `albumFrom` / `albumTo` — только подписи дат, год не нужен.
- Цифры «45 кадров», «30 живых мгновений», «8 глав» считаются сами по фото,
  их менять не нужно.
- Если почему-то поменяли значения в `index.html` в блоке цифр — они не подействуют:
  JS берёт их из `CONFIG` выше.

> После любой правки: `Подготовить к публикации.bat` → `Опубликовать на GitHub.bat`.

### 2. Текст письма
`index.html`, блок `<!-- ПИСЬМО -->` — параграфы `<p class="letter__p">`.

### 3. Имя
- заставка: `.envelope__letterText` («Дашуня, с днём рождения»);
- обложка: `<h1 class="hero__name">Дашуня</h1>`;
- финал: `<span class="finale__name">Дашуня</span>`;
- футер: `<p>для Дарьи · …`.

### 4. Музыка

Сейчас фоном играет **Хаски — «Ветром, снегом, зноем»** (альбом «Партизан», 2025;
320 kbps, 4:11, ≈9,6 МБ) — файл лежит в `assets/music/track.mp3`.

- **Заменить песню:** положите свой файл как `assets/music/track.mp3`
  (подойдут также `.m4a`, `.ogg`, `.wav`, `.flac`, `.aac` — важно имя `track.*`).
  Ничего пересобирать не нужно, файл подхватится сам.
- **Нет файла?** Открытка не сломается: вместо песни заиграет встроенная
  музыкальная шкатулка с мелодией Happy Birthday (синтез на Web Audio, без файлов).
- **Громкость и плавное появление** — в `js/music.js`, объект `CONFIG`
  (`volume`, `duckVolume`, `fadeIn`). Когда в лайтбоксе звучит живой кадр,
  песня автоматически приглушается.
- **Название трека** (плашка «♫ …» и строка в футере) — там же, `CONFIG.title`.

> ⚠️ **Про авторские права.** «Ветром, снегом, зноем» — коммерческий трек,
> и в публичном репозитории GitHub Pages он становится доступен всем.
> Формально это использование без разрешения правообладателя. Для личного
> подарка без рекламы и рассылки риск на практике минимален, но публикуете вы
> это на свой страх и риск. Если хочется совсем «чисто» — оставьте встроенную
> шкатулку или возьмите трек со свободной лицензией.

### 5. Главы, подписи и цитаты
Названия глав, даты, заметки, подписи к кадрам, интерлюдии и состав живой ленты —
в `tools/build_assets.py` (словари `CHAPTERS`, `CAPTIONS`, `INTERLUDES`, `LIVE_STRIP`,
`HERO_POLAROIDS`). После правки:
```
python tools/build_assets.py
```

### 6. Добавить новые фото
Положите оригиналы в `iCloud Photos`, впишите имена в нужную главу в `CHAPTERS`
и запустите `python tools/build_assets.py` — скрипт сам сделает уменьшенные копии,
подхватит парные `.MOV` (Live Photo) и даты из EXIF.

## Что учтено для телефона

- **Тап вместо наведения.** «Живые кадры» помечены бейджем «живой кадр» и по тапу
  открываются полноэкранно **со звуком**.
- **Лайтбокс под палец:** свайп влево/вправо — листать, вниз — закрыть,
  крестик 44×44, отступы под safe-area (не залезает под «чёлочку» и полоску iPhone).
- **Без залипающих hover-эффектов** после касания.
- **Экономия трафика:** в ленте одновременно играет только один кадр,
  видео грузятся по требованию, соседние фото предзагружаются только на быстрой сети,
  при `saveData` и «уменьшить движение» автовоспроизведение отключается.
- **Сначала конверт, потом песня** — мобильные браузеры не дают звучать без касания,
  поэтому музыка стартует ровно в момент, когда она открывает конверт.
- **Первая загрузка лёгкая** (сотни КБ), дальше фото догружаются по мере прокрутки.
- **Подсказки по устройству:** на телефоне «листай в сторону — и нажимай на кадр,
  чтобы услышать» вместо «наведи курсор».

## Структура

```
index.html                      — разметка открытки
css/style.css                   — все стили и анимации
js/app.js                       — логика: рендер альбома, лайтбокс, торт, лепестки
js/music.js                     — музыка: песня из assets/music + запасная «шкатулка»
js/media-data.js                — данные альбома (генерируется)
data/media.json                 — те же данные в читаемом виде
assets/music/track.mp3          — фоновая песня (можно заменить своим файлом)
assets/photos/full/             — большие версии фото (для полноэкранного просмотра)
assets/photos/thumb/            — уменьшенные (для сетки)
assets/live/                    — 30 «живых» видео (.mov, H.264)
tools/build_assets.py           — сборка ассетов и данных из папки iCloud Photos
tools/prepare_publish.py        — папка «Публикация» (+ .nojekyll, robots.txt) для GitHub
tools/check_site.py             — проверка путей перед публикацией
tools/lan_ip.py                 — локальный IP для просмотра с телефона
iCloud Photos/                  — ваши оригиналы (в работе сайта не участвуют)
Публикация/                     — то, что уходит на GitHub (создаётся батником)
```

## Технические заметки про GitHub Pages

- Видео Live Photo — H.264 в контейнере QuickTime с расширением **`.mov`**
  (нижний регистр: GitHub Pages отдаёт MIME по расширению, а таблица mime-db знает
  только нижний регистр — иначе есть риск получить `application/octet-stream`).
  С правильным `video/quicktime` файлы играют в Safari на iPhone и в Chrome.
- `.nojekyll` отключает обработку Jekyll: файлы отдаются как есть, быстрее деплой.
- `robots.txt` просит поисковики не индексировать открытку.
- Пути в проекте только относительные — сайт работает и в корне,
  и в подпапке `github.io/имя-репозитория/`.
- **Фоновая песня** — обычный mp3: GitHub Pages отдаёт его как `audio/mpeg`,
  браузер играет потоково, без полной загрузки файла. Если файл не найден
  или не читается — включается синтезированная шкатулка.
- Фото пересжаты и повёрнуты по EXIF, приватные метаданные (в т.ч. геометки) удалены.
- Уважаются `prefers-reduced-motion` и `saveData`; адаптив от 360 px, горизонтальной
  прокрутки нет.
